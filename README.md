# CET6 Review v2.2.1 — 数据保护与渐进加练版

在 **v2.2.0 完整项目**上增量修改。每日分轮学习、跨天遗忘阶梯、词表、词典、阅读生词与 Supabase 配置沿用原工程。

## 本版四项修改

| 部分 | 修改结果 |
| --- | --- |
| 备份恢复 | 兼容 v2.2.0 的旧格式备份与本版新格式备份；新版记录不再按 2026-10-01 重新迁移。替换数据、写入迁移标记、保存导入前快照在同一事务中进行。 |
| 旧设备同步 | 拒绝 `schedulerVersion < 2` 且日期为 **2026-10-01 及以后**的旧会话；下载、合并、单条上传与本地独有记录上传均检查。此前历史与新版记录正常处理。 |
| 版本缓存 | 核心 HTML / JS / CSS / 配置文件改为网络优先，失败或超时回退缓存。固定词库、词典数据、图标仍为缓存优先。增加资源版本参数、检查更新按钮与非强制刷新提示。 |
| 当天遗忘加练 | 连续遗忘依次隔 **10 → 25 → 50 个队列项 → 队尾**再次出现。队列保存层级，重新打开当天任务仍可续接。认识后不再继续插入当天加练。 |

**跨天规则没有改变：**遗忘词仍按 `1 → 3 → 7 → 14 → 30 天`逐级复习，跨天再次忘记回到 `+1 天`。这是每次成功后到下一次的间隔，不是固定的累计第 1/3/7/14/30 日。

## 原有学习规则

普通轮次点“认识”后，本轮不再按次日回流；全词库完成本轮后进入下一轮。当天到期遗忘词优先安排，剩余名额用当前轮尚未完成的单词补足 **200 个正式单词**；到期遗忘词多于 200 时全部安排，不再加普通轮次词。当天加练不额外增加正式任务配额，但实际作答次数可超过 200。

若当前轮剩余可安排词不足、其它词仍在等待遗忘间隔，当天正式任务可能少于 200；不会为了硬凑数量而提前复习或重复抽取已经完成的词。

“隔 10/25/50 个队列项”不是分钟数，也不保证中间都是不同词。剩余队列不足时直接放队尾；只剩该词时会较快再次出现，不凭空加入新词。第四次及以后仍放在当时队尾。此规则是本次约定的交错练习策略，不能理解成经实验证明的个人最优记忆间隔。

## 更新原网站

1. **更新前**，在正在使用的原 App 设置页导出 JSON 备份，保存到浏览器之外。更新本身不要求导入备份。
2. 解压后，将 `CET6-Review/` **目录里面的内容**覆盖原 GitHub 仓库的同一位置。保持原网站地址、账号与 Supabase 配置，不另建一个新站替代。
3. 等部署完成，关闭电脑与手机上的旧 CET6 标签页/PWA，联网重新打开原网址。设置页底部应显示 **`2.2.1 数据保护与渐进加练版`**。

新 Worker 需要下载并缓存完整资源；旧页面已加载的代码不会凭空改变。旧界面可能还需关闭后重开或普通刷新。新版设置页提供“检查 App 更新”；提示新版本就绪后再点“刷新更新”。**不要通过清除网站数据、删除 IndexedDB、重置学习进度来更新版本。**

本版没有修改 `supabase-config.js`、`supabase-schema.sql`、数据库名称或数据库版本；此次前端更新不要求重新执行 SQL。

详细步骤与恢复说明见 [V2.2.1_UPGRADE.md](V2.2.1_UPGRADE.md)。

## 备份与数据保护

- 新导出备份采用 `schemaVersion: 2`，保存调度版本与迁移完成标记；v2.2.0 的 `schemaVersion: 1` 备份仍支持。
- **v2.2.0 → v2.2.1 不重复清理正常进度**，包括 2026-10-01 及之后由新调度器产生的记录。
- 只有真正的旧调度记录才转换。混合备份逐条保护已有 v2 数据，不单靠 `appVersion` 字样判断。
- 导入前校验格式、主键、日期与可支持的版本。导入中断/写入失败时，替换事务整体回滚。
- 最近一次成功导入前的数据保存在 `appMeta / study-backup-before-import`，可从设置页“导出上次导入前快照”取出；它仍在同一浏览器内，**不等于浏览器之外的独立备份**。
- 导入成功后暂停自动云同步，暂停标记跨刷新保留。核对本地进度后，点击“立即同步”恢复正常合并；这不是用备份强制覆盖云端。
- 所有参与复习的设备都应更新。本客户端的过滤不等于服务器禁止旧设备写入，也不能替代对真实多设备并发的验证。

## 文件与验证

- `scheduler.js`：分轮、到期词选择、递增加练。
- `db.js`：IndexedDB、逐记录兼容迁移。
- `backup.js`：事务式导入、版本识别、快照导出。
- `cloud-sync.js`：旧数据过滤、恢复期间同步协调。
- `service-worker.js` / `pwa.js`：缓存策略与更新提示。
- `tests/`：40 项 Node 自动化测试、13 项页面检查结果与可复跑脚本。
- [TEST_REPORT.md](TEST_REPORT.md)：本次实际测试范围与限制。
- `CHECK_RESULTS.json`：版本/资源/文件哈希检查结果。
- `docs/history/v2.1.3/`：旧版测试结果和旧调度备份文件，仅供追溯，不由 App 加载。

开发者可在项目目录运行 `node --test tests/*.test.cjs`，无须安装 npm 包。测试使用有限的内存 IndexedDB / CacheStorage 模拟器，**不是浏览器磁盘存储或真实 Service Worker 端到端测试**。日常使用不需要 Node、Python 或任何开发环境。
