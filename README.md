# 阅读生词 v3.2.0 · 编辑同步版

只保存、管理阅读中遇到的单词/短语。不包含固定词库、每日任务、间隔复习或学习调度。

## 使用

每张已保存词卡右侧增加 **编辑**。点击后原内容会回填到上方表单，可以修改单词/短语、中文义、来源、原句、备注。点击 **保存修改** 提交，或 **取消编辑** 放弃。

编辑不增加遇见次数，不改变原创建时间；本机词条 ID 保持不变。再次遇见同一个词时，仍可用新增表单“保存”来累计遇见次数。两种操作分开处理。

选填字段允许真正清空。比如删除备注再保存，空备注也会同步，而不是被其他设备的旧备注补回来。单词本身不能为空。

修改拼写会在本机同一事务中更换词头并为旧词头写删除标记。同步后其他设备移除旧词头、出现新词头，不把普通改名计作额外遇见。新词头若已存在于当前本地列表，会阻止保存并提示，不会直接覆盖已有词条。

## 登录与同步

继续使用原 Supabase 项目和同一账号。新增、编辑、清空字段、删除都可以双向同步。离线修改先写入本机，联网后重试。

自动同步触发：登录、启动时恢复账号、本地增删改、恢复联网、切回页面、页面在前台时每 60 秒检查。也可以点击“立即同步”。不是后台实时推送；应用关闭期间不保证同步运行。

### 合并规则

- 不同单词取并集；同一单词按 `normalizedTerm`（忽略首尾空格、连续空白和大小写）匹配。
- 每个可编辑字段独立记录版本。电脑改释义、手机改备注时，合并两处修改；明确清空也是有效修改。
- 同一字段被同时离线修改时，按字段时间决定，时间相同再按设备标识和值稳定裁决。因此不保证保留同一字段的两个互斥版本，也不提供完整编辑历史。设备建议开启自动校时。
- 编辑表单打开后，若已经同步到同字段的其他修改，保存会提示冲突、保留草稿，不直接覆盖。未修改的字段不随旧表单提交。远端删除或改名后，旧表单不能擅自重新创建该词。
- 删除优先于旧副本的普通编辑。用户明确重新添加已经删除的词，才建立新一代词条并重新同步。
- 云端写入使用带版本令牌的条件更新；冲突时重新读取并合并，避免先读后写时盲目覆盖对方的新内容。
- 同步在途时继续新增/编辑，会再次合并当前本地数据并补充同步，不将旧快照覆盖回来。

改名在云端仍是“新词头记录 + 旧词头删除标记”两个记录，不是跨设备即时原子操作。网络中断时可能短暂只同步了一半，重新同步后收敛。若两台离线设备同时把同一词改成不同词头，可能保留两个不同词头，需手工整理；若另一设备在离线期间新增同名词，联网时仍按同名词字段合并规则处理。重要改名前先“立即同步”更稳妥。

## 数据与升级

**数据库保持 `cet6-review-db`，版本仍为 5。** 继续使用 `readingWords` 和 `readingWordTombstones`，不清库、不重建，不执行旧的日期迁移，不修改其他遗留对象仓库。

新增版本信息只存放在词条/删除标记的 JSON 字段中。无须修改云端表结构。`supabase-config.js` 与 `supabase-schema.sql` 均沿用上传项目的原文件；已有账号和权限配置不变。不要再次执行建表脚本或更换项目来升级。

1. 先在目前数据正确的设备点击“立即同步”，确认没有同步错误。
2. 将本包 `CET6-Review` 内的全部文件上传/覆盖到原 GitHub Pages 仓库的对应目录。不要漏传新增的 `sync-model.js`。
3. 保持原网址；不要清除“网站数据”、IndexedDB，也不要卸载后再用清数据的方式重装。
4. 电脑、手机都关闭旧页面/PWA后重新打开，确认页底 **v3.2.0 编辑同步版**，再使用编辑功能。

**所有设备都应更新。** v3.1.0 不理解字段版本和明确清空，继续用旧版修改或同步，可能重新回填已清空内容或丢掉新版元数据。读取旧记录受到兼容保护，不等于允许旧程序继续并行写入。

Service Worker 只更新本 App 静态缓存，不删除学习数据库或登录存储。保持原网址及账号很重要。本机数据仍可能因用户清除网站数据、浏览器存储清理或设备故障而丢失；云同步也不是历史备份。

当前仍是一个浏览器共享一套本地生词，退出登录不会清空本机。更换为另一个账号登录，会按现有设计把本地生词与该账号合并；不要把它用于不同人的账号隔离。

## 项目文件

`app.js` 为页面交互；`db.js` 为本地事务与编辑；`sync-model.js` 为纯数据合并；`cloud-sync.js` 为登录、分页拉取、条件上传与重试。其余为 PWA、样式、图标及原云配置。

`tests/` 只供开发测试，不被 App 或 Service Worker 加载。部署时可省略整个 `tests/` 目录。

## 测试

```sh
node --test tests/*.test.cjs
python tests/test_browser.py
```

第一条不需要安装第三方 Node 依赖。第二条需要 Python Playwright 和 Chromium，可用环境变量 `CHROMIUM_PATH` 指定浏览器路径。

测试范围和限制见 `TEST_REPORT.md`。测试使用模拟数据库/云端，不会读取或更改你的真实账号。
