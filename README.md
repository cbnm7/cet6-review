# CET6 Review v2.1.3 — 词性与释义精简版

基于本次上传的 `CET6-Review(1).zip` 修改。保留 v2.1.2 Supabase 同步、防回退、复习调度和所有个人学习数据结构。

## 这次改了什么

- 原始核心词表 **2003 条记录 / 1992 个唯一词头**，文件、顺序和 ID 不变。
- 1992 个唯一词头逐条编辑：1989 个有精简释义；`mir`、`underly`、`lehman` 不强行解释，明确标记待核对。
- 同一个词按实际保留的词性分别显示，不再把多个词性的中文义项堆在一个标签下。
- 不设“五条释义”配额；每个词按常用程度取舍。不同词性下相同的中文译词不视为无意义重复。
- 删除词典的额外固定搭配、例句、在线多词库拼接和相关展示。今日复习、重点易错专项、两个列表的翻译下拉均使用同一精简词典。
- 保留原词表中已有的 `wipe out` 等词组词头；保留你自己添加的阅读生词、原句和备注，不删除私人资料。
- 释义完整打包，不需要外部词典 API。设置页的“重新载入本地词典”只读取内置数据。
- 老词典缓存只用于延续已缓存的音标；音标不属于本轮逐音审校范围。新设备无旧音标时不编造或强制联网获取音标。

## 更新到 GitHub Pages

1. 更新前先在原 App 设置页导出一份学习数据备份，并确认需要保留的进度已同步。
2. 解压本包，把目录**里面的内容**上传覆盖原仓库根目录；必须包含新增的 `data/concise-dictionary.js` 和 `data/concise-dictionary.json`。
3. 等 Pages 部署完成，在电脑和手机联网重新打开 App。设置页应显示 **2.1.3 精简词典版** 和 **1992 / 1992 词头已整理**，下方明确写 **1989 个有释义、3 个待核对**。
4. 本版首次加载会在同一事务内替换旧词典缓存，仅操作 `cet6-dictionary-db`。如仍看到旧解析，可在新版本设置页点“重新载入本地词典”。
5. 若还显示 v2.1.2，关闭其它旧 CET6 标签页及桌面 PWA，联网打开原网址后刷新，再重新进入。**不要清除网站数据、IndexedDB，也不要重新注册账号。**

不需要重新执行 Supabase SQL；不需要换账号、URL 或 key。保留上传工程中原有的 `supabase-config.js`。

## 数据文件

- `data/cet6_2003.json`：原始复习主表，未修改。
- `data/concise-dictionary.json`：完整可读的精简词典数据。
- `data/concise-dictionary.js`：与 JSON 内容相同的运行时数据，在 `dictionary.js` 前加载。
- `LEXICAL_REVIEW.md`：完整逐词清单，含词性、释义、备注。
- `LEXICAL_REVIEW.json`：逐词机器可读审校记录，关联原 ID。
- `AUDIT_REPORT.md`、`DATA_SOURCES.md`：实际处理范围、核查方式和限制。
- `TEST_REPORT.md`：本次实际执行的检查，以及尚未验证的范围。

日常使用无需安装 Node、Python 或任何开发环境。JSON 和 JS 是同一份数据的两种交付形式；日后改 JSON 时也需要同步生成 JS，不能只改 JSON 而期待运行时自动读取变更。

## 释义范围

这是一份六级与考研阅读**常用义优先的学习稿**，不是官方考纲义项全集，不能保证某个被省略的冷僻义永远不考。全量逐条编辑不等于全量外部词典逐义查证：本轮仅对 8 个重点词头另行访问原站核查；详见审校清单。

英语词性可能随具体句子变化。分词形式与形容词不能只看 `-ed/-ing` 判断；`provided` 等词已加简短词性提示。不是为了简洁就把一个词强行归为唯一词性。
